# Memos 一键复制内容

为 Memos 备忘录卡片增加独立的 `📋 复制内容` 按钮，一次点击复制原始 Markdown，包括折叠正文、空行、代码缩进与 Emoji。

## 2026-10-19 修复

旧版脚本会模拟打开 `⋮ → 复制 → 复制内容`。在 Memos `0.31.0` 的 macOS Edge 上，这段流程实际报错“等待 Memos 菜单超时”。等待菜单渲染后再复制，也不符合 Safari/iOS 对剪贴板用户激活时机的要求。

新版在真实按钮点击中立即调用 `navigator.clipboard.writeText`，不再触发原生菜单或等待异步操作。仅在剪贴板写入成功后显示“已复制”。若浏览器拒绝请求，会提示再次点击；第二次真实点击同步使用兼容复制方式。

## 特点与实现边界

- 从当前正文节点已提交的 React props 读取原始 Markdown，并核对备忘录标识。
- 每次点击重新读取，不缓存正文，不遍历旧 Fiber，不使用 `innerText` 或截断的渲染文本。
- 不发起网络请求，不读取登录凭据，不把正文输出到日志或第三方。
- 自动适配单页应用跳转、列表加载和卡片重新渲染，避免重复按钮。
- 保留按钮原有样式；移动端宽度不超过 640px 时仅显示 `📋` 图标，结果提示仍可见。
- 兼容复制完成或失败后都会清理临时文本框，并恢复焦点与选择区。

读取 `__reactProps$…` 是对 Memos/React 私有渲染结构的定向适配，无法保证未来版本一直兼容。结构或备忘录身份不匹配时会明确报错，不退回复制格式不完整的页面文字。不会通过修改全站剪贴板权限解决问题。

## 兼容性与验证

当前修复部署于 Memos `0.31.0`（Docker / 1Panel），HTTPS 页面。

| 检查 | 结果 |
| --- | --- |
| macOS Edge 真实点击、粘贴核验 | 通过 |
| 中文、Emoji、Markdown 链接、代码缩进、空行 | 系统剪贴板文本与服务器原始正文 SHA-256 完全一致 |
| 10 项 Node 回归测试 | 通过 |
| iOS/Safari 真机 | 本轮没有可用设备，尚未实机验证 |
| Windows / Android 新版脚本 | 本轮未实机复测；保留标准 Clipboard API 路径 |

Safari/iOS 的修复依据是直接在点击事件中发起写入，参见 [WebKit Clipboard API 说明](https://webkit.org/blog/10855/async-clipboard-api/)及[异步边界问题记录](https://bugs.webkit.org/show_bug.cgi?id=222262)。权限被用户或系统禁止时，脚本不会假报成功。

旧版适配 Memos `0.30.0`；本次新版尚未对 `0.30.0` 实机回归。升级 Memos 后应重新测试。

## 安装与升级

1. 备份现有自定义脚本、样式。
2. 管理员打开 **设置 → 系统 → 自定义代码**（具体名称随版本变化）。
3. 将本项目旧复制脚本整体替换为 [`quick-copy-content.js`](./quick-copy-content.js)，不添加 `<script>` 标签。
4. 将本项目旧复制样式替换为 [`quick-copy-content.css`](./quick-copy-content.css)。
5. 保存并刷新 Memos；已安装的 PWA 也需刷新或重新打开。

**如果同时安装了分享快捷按钮或其他自定义功能，只替换复制模块，保留其余代码与样式。** 本次线上部署保留了原有分享定制；仓库中的文件仍是独立复制模块。

卡片右上角显示 `📋 复制内容`。点击后成功提示为“备忘录原始内容已复制”；如果提示重试，再点击一次即可尝试兼容方式。

## 测试

无需第三方依赖，使用支持 `node:test` 的 Node.js：

```sh
node --check quick-copy-content.js
node --test quick-copy-content.test.cjs
```

覆盖原始 Markdown/空内容、编辑后最新内容、嵌套卡片身份验证、未知结构失败、同步发起写入、拒绝时不在异步回调中盲目回退、兼容复制与清理恢复。

## 卸载与回滚

仅删除本项目的 JS/CSS，或还原升级前备份，然后保存、刷新页面。不要清空包含其他定制的整个输入框。数据库中的自定义代码会随正常镜像升级保留，但仍建议定期备份 Memos 数据。
